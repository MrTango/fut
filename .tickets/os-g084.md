# Emit OSC 7501 from first-party agent integrations


## Notes

**2026-10-16T14:51:38Z**

After the core migration, teach integrations/{claude-code,codex,pi} to emit OSC 7501 to /dev/tty instead of calling fut agent report, so they also work in Ghostty and Rex. Preserve CLI fallback for contexts without an accessible tty; update adapter tests.

**2026-10-18T19:45:28Z**

Repro findings (isolated daemon, debug build of e835589). (1) Premise partly wrong: current agents already emit OSC 7501 themselves. Claude Code 2.1.302 and Codex 0.163.0 run in a disposable Fut pane show source=osc, app=claude-code / app=codex in agent list with no plugin; Pi 1.3.0 ships ProgramStatusReporter (gated on the 7501 support query). (2) Claude Code and Codex hooks have no controlling terminal: a probe hook under claude -p, interactive claude, codex exec and interactive codex all ran with pgid=pid, sess 0, tty ??, and opening /dev/tty failed (ENXIO). So hooks cannot emit to /dev/tty on current versions; they must fall back to the CLI. (3) The documented tmux reason for the plugins does not hold: fut agent report from a tmux session started inside a Fut pane is rejected with invalid_agent_context because the tmux server is outside the terminal's process tree, and tmux drops OSC 7501 anyway. (4) Native and CLI lifecycle converge: CLI owner = descendant_root(peer) = agent; native owner = PTY foreground pgrp leader at receipt = agent for hooks spawned by it (hook exit does not clear). Both keep done/error on owner exit.

**2026-10-18T20:01:37Z**

Implemented terminal-first reporting with CLI fallback. Claude report.sh and the Codex adapter write `ESC ] 7501 ; state=S:app=claude-code|codex ESC \` (completed -> done, exited -> bare state=clear) to /dev/tty (Python: O_NOCTTY|O_NONBLOCK; both ignore SIGTTOU) and fall back to `fut agent report` only when that fails; outside Fut with a tty they now report too. Pi writes the same sequence (app=pi) to process.stdout when it is a TTY, keeping it ordered with Pi's own TUI writes; otherwise CLI.

No daemon change needed: a native report from a hook is attributed to the PTY foreground pgrp leader (the agent), so working survives hook exit and is cleaned when the agent exits; done survives agent exit. Same outcome as the CLI's descendant_root owner.

Manual (isolated daemon /tmp/fg084.*): foreground fake agent running Claude/Codex hooks with no Fut env and fut absent -> source=osc working, still working 1.5s after hook exit, cleared on agent exit; claude completed -> done survives agent exit, unread; exited -> clear. Old adapters in the same setup -> nothing. Old adapters under Fut -> CLI (source=report). Real interactive Pi 1.3.0 (PI_PROGRAM_STATUS=0, only this extension) -> osc idle -> working -> done via agent prompt --wait, clear on /quit. Real claude -p (plugin-dir), codex exec (-c hooks, bypass trust) and pi -p (redirected) -> CLI fallback with session ids, then cleared at exit.

Tests: Claude/Codex unit tests now run hooks detached (start_new_session, matching real agents and keeping reports off the developer's terminal) for CLI cases and on a private PTY for native cases. New Codex live test (FUT_LIVE_BIN) checks source=osc, persistence after hook exit and cleanup on agent exit.

Limitation: on current Claude Code and Codex the hook native path is unreachable (hooks are setsid'd), so their plugins remain Fut-only in practice. Making them work in Ghostty/Rex would need writing to the agent's tty device found via process ancestry; not done, needs a decision (interleaving risk with the agent's own output). Codex completion outside Fut also remains open (notify -> fut agent notify codex is CLI-only).
